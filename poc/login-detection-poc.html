🔬 LoginDetection PoC — Vulnerability #2

Open this page in the DuckDuckGo Android browser. DDG will automatically inject window.loginDetectionSecret into this page's JavaScript context. This PoC reads that secret and calls LoginDetection.loginDetected(secret) directly — triggering DDG's real "Fireproof this site?" dialog without any actual login having occurred.

Requirement: DDG Settings → Privacy → "Automatically fireproof sites after login" must be set to Ask every time or Always (not Never).

Expected Result

On a DuckDuckGo Android browser with login detection enabled, DDG will show a native "Fireproof [this site]?" dialog seconds after this page loads — even without submitting the form. The attack has already fired automatically.

Why this matters: Any web page opened in DDG Android can call LoginDetection.loginDetected(window.loginDetectionSecret) immediately after load. The window.loginDetectionSecret variable is injected into every page's JS context by the DDG browser. An attacker-controlled page (phishing site, malicious ad landing page, etc.) can use this to force DDG to treat itself as a "logged-in site" and ask the user to fireproof it — making the malicious site's cookies survive DDG's automatic fire clearing.

Attack Chain

1. User navigates to attacker's page in DDG Android browser

2. DDG's JsLoginDetector.injectLoginFormDetectionJS() fires on onPageStarted:
     webView.evaluateJavascript(
       "javascript:(function(){
          window.loginDetectionSecret = '';   ← injected into THIS page
          [login detection helper functions]
        })()", null)

3. This page's JS polls window.loginDetectionSecret every 50ms

4. As soon as the secret appears, this page calls:
     LoginDetection.loginDetected(window.loginDetectionSecret)

5. LoginDetectionJavascriptInterface.loginDetected(secret) validates:
     this.secret == secret  →  ✅ MATCH  (same UUID)

6. onLoginDetected() fires → BrowserTabViewModel.loginDetected()
     → NavigationAwareLoginDetector.onEvent(LoginAttempt(currentUrl))
     → DDG UI: "Fireproof this site?" dialog appears for THIS PAGE's URL

Pre-fix (vulnerable): loginDetected() took ZERO args — any iframe could fire it.
Current (fixed):      loginDetected(secret) blocks cross-origin iframes that
                      cannot read window.loginDetectionSecret across origins (SOP).
                      But the MAIN FRAME always has the secret injected directly.
