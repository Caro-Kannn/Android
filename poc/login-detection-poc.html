Vulnerability #2: LoginDetectionJavascriptInterface — Login State Spoofing
Open this page in the DuckDuckGo Android browser and press the attack button.

Press "Fire Attack" to run the PoC.

Vulnerability Summary

DDG Android registers a LoginDetection JavaScript interface on its WebView. Any JavaScript in any frame — including cross-origin iframes — can call it.

Pre-fix method (vulnerable):
LoginDetection.loginDetected() — zero arguments, no secret required.
Calling this from any origin triggers DDG's fireproof/credential-save dialog for the current tab's URL without the user having logged in.

Fixed method:
LoginDetection.loginDetected(secret) — secret is a per-session UUID injected into the main frame only. Cross-origin iframes cannot read it via SOP.

Observable impact: DDG's "Fireproof this site?" dialog (or autofill save prompt) appears for this page's origin — even though no real login occurred.

Evidence Log

Expected Results

Vulnerable (pre-fix) build: DDG shows "Fireproof this site?" or credential save dialog for … immediately after clicking "Fire Attack" — despite no actual login having occurred.

Fixed build: No dialog appears. The empty-secret call is silently rejected by the secret check in LoginDetectionJavascriptInterface.loginDetected(secret).

Cross-Origin Demonstration (optional)

The even more impactful scenario is a cross-origin iframe triggering the dialog. In a real attack: a user visits bank.com which embeds an ad or analytics widget from evil.com. The evil.com iframe calls LoginDetection.loginDetected(); DDG shows "Fireproof bank.com?" — tricking the user into fireproofing the victim site on the attacker's behalf.
