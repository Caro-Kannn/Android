How this PoC works

The DuckDuckGo Android browser registers an AutoconsentAndroid JavaScript interface on the WebView using addJavascriptInterface(). This makes the object callable from every frame in the WebView, including cross-origin iframes — Android does not enforce the Same-Origin Policy on @JavascriptInterface calls.

This page embeds a cross-origin attacker iframe (loaded from a different origin) below. The attacker iframe calls AutoconsentAndroid.process(initMessage) — which requires no authentication in the pre-fix code. Android's InitMessageHandlerPlugin processes the message and calls: 

webView.evaluateJavascript(
    "javascript:window.autoconsentMessageCallback(initResp, origin)", null
)

evaluateJavascript() always executes in the main frame's JavaScript context, regardless of which frame triggered the process() call. Our interceptor below detects when this happens and logs what data is accessible — proving the UXSS.

Vulnerable version: AutoconsentAndroid.process(message) — one argument, no secret.
Fixed version: AutoconsentAndroid.process(message, secret) — rejects any call where secret doesn't match the per-session UUID stored in window.autoconsentAndroidSecret (inaccessible from cross-origin iframes via SOP).
